At this point, I don't really care what the non-believers think - if
you are *not* running GNU/Linux, you are wrong. Of course I understand
the need to run dedicated Windows and MacOS machines, when it is out
of your control - say you have a Macbook or need to run it for
%employer. No need to stress about that. But when you are given the
opportunity - given a choice, you should pick whatever Linux-based OS
suits your needs best.

test mkfs.btrfs on 10T dummy block device
#+begin_src shell
  dd if=/dev/zero of=/tmp/bb1 bs=1 count=1 seek=10T
  du -sh /tmp/bb1
  losetup --show -f /tmp/bb1
  mkfs.btrfs /dev/loop0
#+end_src

diagnostics
#+begin_src shell
  iostat # pacman -S sysstat
  blktrace # paru -S blktrace
  iotop # pacman -S iotop
#+end_src

bcc/ trace: Who/which process is executing specific functions against
block devices?

bcc/biosnoop: Which process is accessing the block device, how many
bytes are accessed, which latency for answering the requests?

at the kernel level besides BPF we got kmods and DKMS,

compression/de-duplication can be done via VDO kernel mod
